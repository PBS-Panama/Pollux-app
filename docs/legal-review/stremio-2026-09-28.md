# Informe de revisión legal — limpieza de código Stremio/GPL en Pollux

**Fecha:** 2026-09-28. **Preparado por:** developer de Pollux, a pedido del PM, para revisión
legal de Rick. **Alcance:** `products/portal/pbsds-pollux-app/interfaces/leto/` — la SPA de
crewing (Pollux company-side), fork original de [stremio-web](https://github.com/Stremio/stremio-web).

Este documento resume todas las fases de trabajo, documenta cada excepción con su evidencia, y
da el método + los archivos exactos para que cualquiera reproduzca los números. No se hizo ningún
commit ni push de `pb-website` durante este trabajo (salvo T1, explícitamente autorizado y acotado
al repo remoto `PBS-Panama/Pollux-app`, ver sección T1).

## 1. Origen y punto de partida

`interfaces/leto/` nace como un fork de `stremio-web` (licencia **GPL-2.0**, ver `LICENSE.md` en
la raíz de `pbsds-pollux-app`). El trabajo documentado acá cubre la reescritura progresiva de ese
fork en código propio de Pollux — maritime crewing, no streaming — a lo largo de 14 fases
numeradas (R1-R14) más 2 tareas de infraestructura (T1, T2) y una limpieza final de archivos
sueltos. El commit de referencia usado en todo el análisis de similitud es
`091f94e8` en la rama `development` de `PBS-Panama/Pollux-app` (un snapshot cercano al fork
original, antes de que empezara cualquier fase de reescritura — no es un commit del repo upstream
de Stremio directamente).

## 3. Excepciones — techo real documentado

Una "excepción" es un archivo que sigue mostrando similitud alta o media con el `091f94e8` original
sin que haya una forma genuinamente distinta de escribirlo. Categorías, con ejemplos:

- **CSS de valor exacto**: para lograr el mismo resultado visual pixel a pixel, una declaración
  como `display: flex; gap: 0.5rem;` solo se puede escribir de una forma. Ejemplos: `Settings.less`
  (94.1%), `App/styles.less` (79.1%), `Button.less` (72.7%).
- **Tipos/datos que reflejan una forma real**: un tipo TypeScript que describe la forma real de un
  objeto (ej. `common/Shortcuts/types.d.ts`, `routes/Settings/constants.ts`) no tiene un "diseño
  alternativo" — inventar otra forma sería un tipo incorrecto.
- **Barrels triviales**: un re-export de una o dos líneas (`export { default } from './X'`) tiene
  una sola forma razonable de escribirse.
- **Lógica con techo real tras reintento genuino**: los 5 casos de la tabla de arriba — cada uno
  fue reintentado con una descomposición o manejo de estado distinto, y lo que queda compartido con
  el original es contrato de props/estructura de datos irreducible, no falta de esfuerzo.
- **Calendar.less — CSS genérico, caso especial** (ver sección siguiente): 66.7% de similitud, pero
  las 12 líneas compartidas son puramente `display: flex`/`gap`/`width`/`height`/media query —
  mismo patrón que el resto de las excepciones CSS, revisado línea por línea antes de clasificarlo
  así.

Ningún archivo quedó en "excepción" sin evidencia escrita — todas están en
`r14-excepciones-consolidado-2026-09-28.md` (29 de ALTA) y `clasificacion-media-baja-2026-09-28.md`
(el resto).

## 9. Qué queda para poder quitar `LICENSE.md`

`LICENSE.md` (GPL-2.0, heredado del fork de stremio-web) sigue en el repo porque todavía queda
código con contenido real del original, documentado como excepción en las secciones 2-4 de este
informe:

- **29 archivos del grupo ALTA** (R14) — CSS de valor exacto, tipos/datos sin diseño alternativo,
  barrels triviales, y 5 componentes con lógica que llegaron a un techo real tras reintento
  genuino.
- **Calendar.less** — CSS genérico congelado por decisión de Rick, sin tocar.
- El resto del código (R1-R13, T1, T2, y los 57 de MEDIA/BAJA) ya no tiene contenido derivado —
  o fue borrado, o fue reescrito de cero, o es dato/estructura propia de Pollux que nunca vino del
  original (confirmado con evidencia archivo por archivo).

**Recomendación (no es una decisión legal, es la lectura del dev):** los 29 archivos ALTA
restantes son, en su enorme mayoría, declaraciones CSS de valor exacto y tipos/barrels sin margen
de diseño — el tipo de contenido que licencias de software libre en general no consideran
protegible por derecho de autor de forma aislada (hechos/ideas funcionales, no expresión
creativa), pero esa es una lectura técnica, no un veredicto legal. La decisión de si eso alcanza
para quitar `LICENSE.md`, o si hace falta reescribir/eliminar también esos 29 (y qué hacer con
Calendar.less) le corresponde a Rick con asesoría legal — no es algo que el dev pueda decidir
unilateralmente. Mientras no haya esa decisión, `LICENSE.md` se mantiene en el repo.
