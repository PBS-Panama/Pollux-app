### 3.4 Unificación de autenticación — bridge localStorage

**Problema:** Dos mundos separados:
- Landing page usa Zustand + JWT (`leto-auth` en localStorage)
- Crewing module corría con auth de Stremio (core transport) → mostraba "Anonymous user"

**Solución:** Puente via `localStorage['leto-user']` — mismo origen (`localhost:3000`), misma storage.

#### Flujo completo

```
Landing page (login/register)
  → POST /api/auth/login → { access_token, refresh_token }
  → GET  /api/auth/me    → { id, email, first_name, last_name, rank, ... }
  → POST /crewing-api/users/{UUID}/init   ← crea carpeta de usuario por UUID
  → GET  /crewing-api/users/{UUID}/settings ← lee rank guardado
  → localStorage.setItem('leto-user', { id, email, rank, first_name, last_name })
  → navigate('/dashboard') → iframe carga /app/

Crewing module (NavMenuContent.js)
  → lee localStorage['leto-user']
  → muestra seafarer card con nombre real + rank
  → botón "Cerrar sesión" → borra leto-auth + leto-user → window.top.href = '/'
```

#### Archivos modificados

**`src/common/apiClient.js`**
```js
// Antes:
const DEFAULT_USER_ID = 'SF-001';

// Después:
const getUserId = () => {
    try {
        const data = localStorage.getItem('leto-user');
        if (data) return JSON.parse(data).id || 'SF-001';
    } catch {}
    return 'SF-001';
};
```
Exportado como `api.getUserId()` — todos los módulos lo llaman dinámicamente.

**`src/common/seafarerStore.js`**
- `const userId = api.DEFAULT_USER_ID` (nivel de módulo, evaluado una vez) → eliminado
- Todos los API calls usan `api.getUserId()` inline

**`src/routes/Library/useDocumentUpload.js`**
- `const userId = api.DEFAULT_USER_ID` dentro del hook → `api.getUserId()`

**`src/components/NavBar/HorizontalNavBar/NavMenu/NavMenuContent.js`** — **reescrito**
- Eliminados: `useProfile`, `useStreamingServer`, `useTorrent`, `useServices`, Stremio core dispatch
- Agregado: `getLetoUser()` lee `localStorage['leto-user']`
- Seafarer card: muestra nombre (first_name + last_name o email prefix), rank, status "Validado"
- Logout: `localStorage.removeItem('leto-auth')` + `localStorage.removeItem('leto-user')` + `window.top.location.href = '/'`
- Escucha evento `storage` para detectar login desde ventana padre

**`frontend/src/components/LoginModal.tsx`**
- Post-login: init crewing folder por UUID, fetch rank, escribe `leto-user`

**`frontend/src/components/RegisterModal.tsx`**
- Post-registro: init crewing folder por UUID (reemplaza SF-001), sync rank, escribe `leto-user`

**`frontend/src/pages/Dashboard.tsx`**

- El iframe de `/app/` ahora ocupa `100vh` completo

### 3.5 Migración de datos SF-001 → UUID

**Contexto:** Todos los usuarios compartían la carpeta `User database/SF-001/`. El usuario `demo@leto.com` tiene UUID `f703542f-cf4d-48eb-aa5f-764a610c7adb`.

**Comparación de contenidos:**

| Carpeta | settings.rank | calendar | myfiles | dashboard |
|---|---|---|---|---|
| `SF-001/` | `"master"` | 5 períodos reales | vacío | vacío |
| UUID/ | `null` | vacío | vacío | vacío |

**Acción:** Copiados `settings/data.json` y `calendar/data.json` desde SF-001 → UUID.

```bash
docker exec leto-crewing-1 sh -c '
  UUID="f703542f-cf4d-48eb-aa5f-764a610c7adb"
  BASE="/app/User database"
  cp "$BASE/SF-001/settings/data.json" "$BASE/$UUID/settings/data.json"
  cp "$BASE/SF-001/calendar/data.json" "$BASE/$UUID/calendar/data.json"
'
```

**Resultado:** El usuario demo tiene rank `master` y sus 5 entradas de calendario preservadas bajo su UUID real.

### 3.6 Fix: FastAPI Swagger UI inaccesible en `/api/docs`

**Problema:** `http://localhost:3000/api/docs` retornaba 404.

**Causa raíz:** FastAPI sirve sus docs en `/docs` internamente. Nginx mapea `/api/` → `backend:8000/api/`. El resultado era:
```
localhost:3000/api/docs  →  nginx  →  backend:8000/api/docs  →  404
                                       (FastAPI busca /docs, no /api/docs)
```
Las rutas de auth funcionaban porque el router ya tenía el prefijo `/api/auth` definido. Los docs no tenían ese prefijo.

**Fix — `backend/app/main.py`:**
```python
app = FastAPI(
    title="Leto API",
    docs_url="/api/docs",
    redoc_url="/api/redoc",
    openapi_url="/api/openapi.json",
)
```

El backend tiene `--reload` en Docker, por lo que tomó el cambio sin rebuild.

**Resultado:** Las tres URLs están activas:
- `http://localhost:3000/api/docs` — Swagger UI ✅
- `http://localhost:3000/api/redoc` — ReDoc ✅
- `http://localhost:3000/api/openapi.json` — Schema raw ✅

**Solución planificada:** Crear ruta nueva `#/my-profile` con componente dedicado que lea desde `crewing-api` y renderice una vista similar a MetaDetails. Ver `docs/NEXT-SESSION.md` para el plan detallado.
