# Session 2026-04-10 — Phase 1 Completion, Career Profile, STCW Matrix Integration

## Context

Continuation of the Phase 1 roadmap (Data Foundation and Compliance Core). The previous session (2026-04-03) established the crew database, assignment CRUD, and initial STCW matrix. This session focused on closing Phase 1 exit criteria gaps, building the Career profile section, migrating profile persistence to PostgreSQL, and integrating the STCW matrix into all consumer pages.

### 2. Phase 1 Exit Criteria Gaps Closed

**Passport expiry inputs:** Added Passport 1 and Passport 2 expiry date inputs to the Mobility Profile form, plus visa type and visa expiry fields.

**Visa-to-passport linking validation:** Added `profile-visa-link-consistency` rule to `stcwMatrix.js` that flags visa linked to Passport 2 without double nationality enabled. Save is blocked with an inline error in the UI, and the matrix reports it as a travel blocker.

**Recruiter visa/nationality filter:** Built `GET /crewing-api/users/mobility-summary?ids=a,b,c` endpoint that returns compact visa/nationality/passport data for bulk crew enrichment. Added a 4th "Mobility / Visa" filter column to the Crew Database with 5 options: Has visa, No visa, Double nationality, Visa linked to Passport 1, Visa linked to Passport 2.

### 3. Mobility Profile Form — Relocated and Restructured

Removed the Mobility Profile from My Files (Library.js) and rebuilt it in My Profile (MyProfile.js) in the seafarer panel below About Me.

**New layout:** Each logical section on its own horizontal row inside a labelled section card:
- Identity (Primary nationality, optional Secondary)
- Passport 1 (Number, Country, Expiry)
- Passport 2 (conditional — Number, Country, Expiry)
- Visa (conditional — Number, Country, Type, Expiry, Linked passport)
- Travel (Departure airport IATA, name)

Header bar with title + "Double nationality" and "Has visa" toggles on the right, Save button.

**Live readiness pills:** Travel blocks, Certification window 90d, Expired — re-evaluate on every keystroke before save.

Renamed "Matrix blockers" → "Travel blocks" everywhere.

### 4. Career Section — Rank Selection Post-Onboarding

**Problem:** No way to change rank after registration.

**Solution:** Built a new `CareerSection` component in MyProfile.js with:
- Rank dropdown (DarkDropdown, 10 STCW ranks with icons)
- Years of experience input
- Available for work toggle
- Rank-change confirmation modal explaining compliance recalculation impact
- Rank-specific notes (same content as RegisterModal)
- Save Career button that PATCHes `/api/seafarers/me`

**Rank persistence chain:** On save, rank is written to:
1. PostgreSQL `seafarers.rank` via `PATCH /api/seafarers/me`
2. Crewing filesystem `settings.rank` via `updateUserSettings`
3. `leto-user` localStorage for immediate sidebar/dashboard reflection

### 5. Profile Persistence Migration — localStorage → PostgreSQL

**New backend endpoint:** `PATCH /api/seafarers/me` accepts partial updates for: rank, city, years_experience, bio, is_available, nationality, phone, first/last name, dob, languages, vessels_worked, companies_worked.

**New backend endpoint:** `POST /api/auth/refresh` accepts a refresh_token and returns fresh access/refresh tokens.

**`/api/auth/me` expanded:** Now returns nationality, phone, city, years_experience, bio, languages, vessels_worked, companies_worked, is_available (were previously missing).

**Frontend MyProfile rewrite:**
- Reads all profile data from `/api/auth/me` on mount
- City, Bio, Languages, Vessels, Companies all PATCH to `/api/seafarers/me`
- `authFetch` wrapper retries 401s with token refresh
- Dropped localStorage for profile identity fields (only CompanyProfile extra fields remain in LS)

**Schema changes:**
- Added `city` VARCHAR(120) to `seafarers` table
- Added `languages`, `vessels_worked`, `companies_worked` VARCHAR(500) to `seafarers` table

**Onboarding updated:** RegisterModal Step 1 now collects City and Years of Experience for seafarers, submitted in the register payload.

### 8. Bug Fixes

**Token expiry "Invalid or expired token":**
- Bumped `ACCESS_TOKEN_EXPIRE_MINUTES` from 15 → 60
- Added `POST /api/auth/refresh` endpoint
- Added `authFetch` wrapper in MyProfile that retries 401s with token refresh

**Doc count mismatch (32 vs 28):**
- Root cause: em-dash `—` in crewDocData.js vs hyphen `-` in stcwMatrix.js for 4 IMO titles
- Fixed by normalizing all titles in stcwMatrix.js to em-dash
- Added missing `IMO 1.14 — Medical First Aid` to UNIVERSAL_DOCUMENTS

**Rank not loading in My Exams/My Files:**
- Root cause: `updateSettings` wrapped payload in `{ preferences: {...} }`, writing rank as `preferences.rank` instead of top-level `rank`
- Fixed by switching to `updateUserSettings` which does direct shallow merge
- Added localStorage fallback for rank reading in all consumers

**Native select dropdown white on dark theme:**
- Replaced native `<select>` with existing `DarkDropdown` component for rank selector

**Legacy rank labels not matching canonical IDs:**
- Added `isCanonicalRank()` check — if stored rank doesn't match an ID, dropdown starts empty for user to re-pick

### API endpoints implemented
| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | /api/auth/register | User registration (seafarer + company) |

| GET | /api/auth/me | Full user profile |
| PATCH | /api/seafarers/me | Update seafarer profile |
| GET | /api/companies/{id}/vessels | List company vessels |
| POST | /api/companies/{id}/vessels | Add vessel |
| GET | /api/companies/{id}/crew | List all seafarers (for company) |

| POST | /api/companies/{id}/vessels/{vid}/assignments | Create assignment |
| PATCH | /api/companies/{id}/assignments/{aid} | Update assignment |
| DELETE | /api/companies/{id}/assignments/{aid} | Delete assignment |
