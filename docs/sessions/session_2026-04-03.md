## 1. My Files — PDF preview fixed for UUID users

Resolved a data path bug in `Library.js` where document preview, metadata refresh, rotate, and download URLs still used `api.DEFAULT_USER_ID` (`SF-001`) instead of the logged-in user's UUID.

### Impact

- Uploads were stored under the correct UUID folder
- Preview/download/rotate requests were still targeting the legacy `SF-001` folder
- Result: uploaded PDFs existed on disk but failed to preview for real users

### Change

Replaced all remaining `api.DEFAULT_USER_ID` references in Library flows with `api.getUserId()`.

**Archivo:**
- `src/routes/Library/Library.js`
