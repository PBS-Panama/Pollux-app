### Arquitectura del componente

**Decisión clave:** En vez de construir el panel de perfil desde cero, MyProfile **reutiliza los componentes internos de MetaPreview** directamente:

```js
const MetaLinks = require('stremio/components/MetaPreview/MetaLinks');
const ActionButton = require('stremio/components/MetaPreview/ActionButton');
const metaPreviewStyles = require('stremio/components/MetaPreview/styles');
```

Esto garantiza que el perfil del usuario se ve idéntico al perfil de un tripulante en el crew database (mismos tags, mismos botones de acción, misma tipografía).

### Panel izquierdo — Campos editables

Cada campo usa componentes inline editables:
- **`InlineField`** — para City/Exp (se editan en línea sin romper el flujo)
- **`EditableMetaLinks`** — para Languages/Vessels/Companies (muestra tags cuando tiene datos, input cuando está vacío o en edición)
- **`EditableAbout`** — textarea para About Me

**Persistencia:** Los campos editables se guardan en `localStorage['leto-profile-extra']`. El botón "Guardar cambios" solo aparece cuando hay cambios sin guardar (dirty tracking).

**Datos del backend:** Nombre, rank, email y age vienen de `localStorage['leto-user']` (set durante login).

### Panel derecho — Documentos requeridos por rango

No muestra documentos subidos por categoría (eso es My Files). En cambio, muestra **todos los documentos requeridos para el rango del usuario** según la matriz STCW (`RANK_REQUIRED_DOCS`), con status:
- **VALID** — subido y vigente
- **EXPIRING** — subido pero vence en <90 días
- **EXPIRED** — subido pero vencido
- **MISSING** — no subido

Botón inferior: **"Agrega tus documentos (X faltantes)"** → navega a `#/myfiles`.

### Unsaved changes guard

Cuando hay cambios sin guardar y el usuario intenta navegar:
1. Se intercepta `hashchange` + `popstate` + `beforeunload`
2. Se restaura el hash a `#/my-profile`
3. Se muestra modal con blur animado:
   - "Cambios sin guardar — ¿Deseas descartarlos?"
   - "No, volver" / "Sí, descartar"
4. Si descarta → revierte campos + navega al destino pendiente
5. Si cancela → cierra modal, se queda en la página

## 2. Endpoint `/me` enriquecido

### Archivos modificados

| Archivo | Cambio |
|---|---|
| `backend/app/schemas/auth.py` | `UserResponse` ahora incluye `rank`, `first_name`, `last_name`, `date_of_birth` |
| `backend/app/routers/auth.py` | `/me` hace JOIN con tabla `Seafarer` para poblar los campos |

### Antes vs después

```python
# Antes
@router.get("/me")
def me(current_user: User = Depends(get_current_user)):
    return current_user  # solo id, email, role, company_id, created_at

# Después
@router.get("/me")
def me(current_user: User = Depends(get_current_user), db: Session = Depends(get_db)):
    seafarer = db.query(Seafarer).filter(Seafarer.id == current_user.id).first()
    return UserResponse(
        id=current_user.id, email=current_user.email, role=current_user.role,
        company_id=current_user.company_id, created_at=current_user.created_at,
        rank=seafarer.rank if seafarer else None,
        first_name=seafarer.first_name if seafarer else None,
        last_name=seafarer.last_name if seafarer else None,
        date_of_birth=seafarer.date_of_birth if seafarer else None,
    )
```

## 4. Age display + fallback

MyProfile calcula la edad desde `date_of_birth`:

```js
const age = now.getFullYear() - birth.getFullYear();
// ajustado por mes/día
```

**Fallback:** Si `date_of_birth` no está en `localStorage['leto-user']` (sesión vieja), MyProfile lee el JWT de `localStorage['leto-auth']`, llama a `/api/auth/me`, obtiene `date_of_birth`, y actualiza `leto-user` para futuras visitas.
