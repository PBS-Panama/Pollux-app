## 1. MyProfile.js — 3-Column Header Grid

### Final grid proportions
```
gridTemplateColumns: '5fr 9fr 6fr'   // 25% | 45% | 30%
```

After several iterations the user settled on this percentage-based layout:
- **Col 1 (5fr / 25%)** — Avatar circle + Nombre/Apellido below
- **Col 2 (9fr / 45%)** — Category chip + Age / City / Exp + Rank chip
- **Col 3 (6fr / 30%)** — Insignia card (placeholder)

### Previous attempts and why they failed
| Attempt | Problem |
|---------|---------|
| `9.24rem 1fr 9rem` (fixed) | Increasing Col 3 to 11rem expanded the overall card and stretched the avatar |
| `9.24rem minmax(0,7.5rem) 9rem` | Constrained Col 2 too much — opposite extreme |
| `5fr 9fr 6fr` | Correct — all columns proportional, card stays stable |

### Rank chip moved: Col 3 → Col 2
The `Master (Capitán de Buque)` chip was moved from below the Insignia card to Col 2, **below the Exp row**, inside `runtime-release-info-container`. Display changed to `inline-block`.

### Insignia card shrunk 20%
Wrapped the aspect-ratio card div in `<div style={{ width: '80%', margin: '0 auto' }}>` — reduces visible card size without changing the column proportion.

### Col 3 padding
`padding: '0 0.6rem'` on the outer Col 3 flex container — keeps Insignia centered within its column.

## 2. MyProfile.js — EditableText `style` Prop

Added `style` (aliased as `extraStyle`) to the `EditableText` component's destructured props. All three render paths (editing input, pill placeholder, plain span) now call `Object.assign({...existingStyle}, extraStyle)`.

**Why:** inherited font-size was being overridden by ancestor CSS rules. Direct inline style on the span bypasses specificity issues.

Used to apply `{ fontSize: '1.25rem', fontWeight: 600, color: '#c0c8d8' }` to firstName and lastName EditableTexts — matching the rank chip styling exactly.

## 3. MyProfile.js — Avatar Upload Pipeline Fixes

### Problem: Avatar POST returned 401
`userId` was null in the `handleCropSave` closure. `user.id` was null in `leto-user` localStorage and `api.getUserId()` returned the legacy fallback `'SF-001'` which doesn't exist in the DB.

### Fix: fresh uid resolution
```js
var uid = userId || (function() {
    try { var d = localStorage.getItem('leto-user'); if (d) { var p = JSON.parse(d); if (p && p.id) return p.id; } } catch (e) {}
    return null;
})();
if (!uid) {
    // No active session — save avatar locally only (dev/demo mode)
    ...
    return;
}
```
`uid` is resolved fresh inside `handleCropSave`, reading directly from `leto-user` localStorage. If still null → local-only save (dev/demo fallback, no backend call).

### Problem: Cropper vs display mismatch
Avatar img had `height: 130%; transform: translateY(...)` — legacy hack for the placeholder image that distorted uploaded avatars.

**Fix:** `style={{ width: '100%', height: '100%', objectFit: 'cover', display: 'block' }}` on the avatar `<img>`.

## 4. MyProfile.js — handleSave: Sync Names to localStorage

`handleSave` previously synced only `rank` and `department` to `leto-user`. Added `first_name` and `last_name`:

```js
localStorage.setItem('leto-user', JSON.stringify({
    ...stored,
    rank: profileRank || null,
    department: department || null,
    first_name: firstName || null,
    last_name: lastName || null,
}));
```

**Why:** `Compliance.js` reads `leto-user` to build the `user` object for `ProfilePreviewCard`. Without this, the card always showed "Su Perfil".

## 5. Compliance.js — ProfilePreviewCard Fixes

### Name: "Su Perfil" placeholder bug
`user.first_name` / `user.last_name` were not in `leto-user` (only saved to `leto-profile-extra` as `firstName`/`lastName`). Fix in two places:

**Compliance.js `user` memo** — added explicit fallback:
```js
first_name: lu.first_name || profileExtra.firstName || null,
last_name:  lu.last_name  || profileExtra.lastName  || null,
```

**MyProfile.js `handleSave`** — writes `first_name`/`last_name` to `leto-user` on save (see §4).

### Avatar display: circular format
Changed from `width: 100%; height: 100%; objectFit: cover` (face fills entire poster) to:

```js
// Container
display: 'flex', alignItems: 'flex-start', justifyContent: 'center',
paddingTop: '8%', overflow: 'hidden'

// img
width: '75%', aspectRatio: '1 / 1',
objectFit: 'cover', objectPosition: 'center',
borderRadius: '50%'
```

**Why:** The circular avatar (JPEG with white corners from canvas clip) must be displayed as a circle to match the default `profileimg.png` placeholder (Leto silhouette). `border-radius: 50%` hides the white JPEG corners without changing the cropper export format.

## 8. Known Constraints

- **Avatar is JPEG** — canvas `toDataURL` exports JPEG; transparent pixels become white. `border-radius: 50%` in CSS handles this without changing the export. If true transparency is needed in the future, change to `canvas.toDataURL('image/png')`.
- **Name sync requires Save** — for existing sessions that never re-saved after this fix, `leto-user` may lack `first_name`/`last_name`. The `profileExtra` fallback in `Compliance.js` handles this case (reads from `leto-profile-extra` which IS written on every save).
- **Auth gap in crewing SPA** — users accessing `/app/` without the Vite React login flow have no JWT. Avatar saves locally in this case (dev/demo mode). Full auth unification is deferred.
