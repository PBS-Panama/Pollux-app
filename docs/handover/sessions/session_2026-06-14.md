```

  → Resultado: verified | wrong_document | suspicious | likely_fake
  → Si rechazado: seafarer puede "Solicitar Revisión Humana"
  → Admin ve el caso en Review Queue con visor de archivo inline
  → Admin aprueba o rechaza (con motivo)
  → Caso se cierra → pasa a tab Auditoría
  → Seafarer recibe notificación en campana 🔔 (Cástor topbar)
```

## Bugs corregidos

### Bug 1 — Rechazo no llegaba al user panel
**Causa:** `useDocumentUpload` solo hace refetch on mount o evento `pbs-uploads-changed`. El admin podía rechazar un doc mientras el seafarer estaba en Library y el cambio no se reflejaba.  
**Fix:** `AlertsButton` detecta cuando llegan notificaciones nuevas (comparando `list.length > prev.length`) y despacha `pbs-uploads-changed`, forzando un refetch de la lista de docs.

### Bug 2 — Caso no desaparecía de la queue tras decisión del admin
**Causa:** La query `pending-review` usaba:
```sql
WHERE verification_status IN ('under_review','wrong_document')
   OR (ai_verdict->>'status') IN ('suspicious','likely_fake','wrong_document')
```
Al rechazar, `verification_status` cambiaba a `'rejected'` (primera cláusula = FALSE) pero `ai_verdict.status` seguía siendo `'wrong_document'` (segunda cláusula = TRUE) → el caso permanecía en la cola indefinidamente.  
**Fix:** La query activa ahora antepone `AND verification_status NOT IN ('verified','rejected')` como condición excluyente.

### Flujo OCR completo a verificar

1. **Doc correcto** — subir National ID Card → modal OCR → debe salir `✅ Documento Admitido` con confianza >80%.
2. **Doc incorrecto** — subir Passport como National ID Card → modal OCR → debe salir `❌ Documento Incorrecto`, identificado como Passport.
3. **Solicitar Revisión** — en el modal de rechazo, click "Solicitar Revisión" → estado cambia a `🔍 En revisión`.
4. **Admin Review Queue** — login como admin → Review Queue tab Activos → ver el caso con badge "👤 Seafarer solicitó revisión" → click "🔎 Ver archivo" → imagen/PDF carga inline.
5. **Admin rechaza con motivo** — escribir motivo → "Confirmar rechazo" → el caso desaparece de Activos → aparece en tab Auditoría con sello "Caso cerrado — Rechazado".
6. **Notificación al seafarer** — volver a Cástor → campana 🔔 muestra badge rojo → dropdown muestra "❌ Rechazado — Motivo: ...". Doc list también actualizado inline con estado "❌ Rechazado" y razón.
7. **Admin aprueba** — probar el flujo alternativo: admin aprueba → caso a Auditoría con sello "✅ Aprobado" → campana del seafarer muestra "✅ Verificado".
