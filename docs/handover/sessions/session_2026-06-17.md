## Compliance Card — Estructura de avatar ✅ APROBADA

### Archivo
`interfaces/castor/src/routes/Compliance/Compliance.js`
Componente: `ProfilePreviewCard` — bloque "Poster image layer"

### Estructura final (probada y aprobada 2026-06-17)

```jsx
{/* Poster image layer — circular, 60% del card, 80px arriba del centro */}
<div style={{
    position: 'absolute',
    top: '50%', left: '50%',
    transform: 'translate(-50%, calc(-50% - 80px))',
    width: '60%', aspectRatio: '1 / 1',
    overflow: 'hidden',
    borderRadius: '50%',
}}>
    <img
        src={avatarSrc}
        alt={fullName}
        loading="lazy"
        style={{
            width: '100%', height: '100%',
            objectFit: 'cover',
            objectPosition: (user && user.avatar) ? 'center center' : 'center calc(50% + 23px)',
            display: 'block',
        }}
        onError={function(e) { e.target.src = 'images/profileimg.png'; }}
    />
</div>
```

### Decisiones de diseño

| Parámetro | Valor | Razón |
|---|---|---|
| `width` | `60%` | 50% base + 20% incremento proporcional |
| `aspectRatio` | `1 / 1` | Fuerza cuadrado — `height: 60%` causaba rectángulo portrait por el `paddingTop` trick del card |
| `transform` | `translate(-50%, calc(-50% - 80px))` | Centrado horizontal, 80px arriba del centro vertical del card |
| `borderRadius` | `50%` | Circular — consistente con MyProfile. `0.5rem` causaba rectangulo visible con avatar real |
| `objectFit` | `cover` | Llena el contenedor sin deformar |
| `objectPosition` | `center center` (avatar propio) / `center calc(50% + 23px)` (placeholder) | Replica patrón de MyProfile — el placeholder tiene la cara posicionada más abajo en la imagen |

### Bug corregido en esta sesión

**Síntoma:** Al cargar un avatar real (no el placeholder), el card mostraba un rectángulo portrait desproporcionado.
**Causa:** `height: '60%'` se resuelve sobre la altura real del card (`paddingTop: calc(100% * 1.464)`), produciendo un contenedor más alto que ancho.
**Fix:** `height: '60%'` → `aspectRatio: '1 / 1'` + `borderRadius: '50%'`.

### Consistencia MyProfile ↔ Compliance

Ambos módulos usan la misma lógica `objectPosition`:
- Avatar propio subido → `center center`
- Placeholder `profileimg.png` → `center calc(50% + 23px)`

Cuando el usuario carga y croppea su foto en MyProfile, `user.avatar` queda como base64 JPEG 200×200, y **ambos módulos la muestran correctamente** sin configuración adicional.

### Evolución del diseño

| Versión | Descripción | Estado |
|---|---|---|
| Original | `width:75%, borderRadius:50%, paddingTop:calc(8%+40px)` | ❌ imagen cortada arriba |
| v2 | full-fill `inset:0, 100%×100%` | ❌ demasiado grande |
| v3 | `50%×50%` centrado | ❌ muy centrado verticalmente |
| v4 | `60%×60%`, `translate(-50%, calc(-50% - 80px))`, `borderRadius:0.5rem` | ❌ rectángulo con avatar real |
| **v5 (aprobada)** | `60%`, `aspectRatio:1/1`, `borderRadius:50%`, `translate(-50%, calc(-50% - 80px))` | ✅ probada con avatar real |

## Cropper de avatar — Scroll Wheel Zoom ✅ APROBADO

### Archivo
`interfaces/castor/src/routes/MyProfile/MyProfile.js`
Elemento: `<canvas ref={cropCanvasRef} ...>`

### Cambio

```jsx
onWheel={function(e) { e.preventDefault(); handleCropZoom(e.deltaY < 0 ? 0.1 : -0.1); }}
```

- Scroll arriba (`deltaY < 0`) → zoom in (`+0.1`)
- Scroll abajo (`deltaY > 0`) → zoom out (`-0.1`, limitado a `cropMinScale`)
- `e.preventDefault()` evita que la página haga scroll mientras se usa el cropper
- Delta `0.1` consistente con los botones `−` / `+` existentes
