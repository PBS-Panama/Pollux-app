# Sesión 2026-09-10 — Admin: consolidación, credenciales reales, menú de perfil, checkout único

Ver el detalle completo de cada bloque en `Handover.md` (buscar "SESIÓN 2026-09-10"). Resumen:

## 1. Admin panel — Pollux como único acceso
- Confirmado que el admin panel ya vivía únicamente en Pollux (nginx/compose de Castor no tienen
  ninguna ruta `/admin/`).
- Arreglada la conectividad Pollux→Castor rota desde el split del 2026-09-03: nueva variable
  `CASTOR_BASE_URL` (`app/core/config.py`) en vez de 4 hardcodes a `http://castor:8080`; red
  compartida `pbs-cross-app` entre los dos docker-compose locales; plantilla de Cloud Run
  actualizada (Castor aún sin desplegar, así que el valor de producción queda listo pero inerte).
- Eliminada una segunda copia embebida y desactualizada del admin panel dentro de `landing`
  (le faltaban 3 páginas reales: Review Queue, OCR Feedback, OCR Manager). `LoginModal.tsx` ahora
  hace una carga de página completa a `/admin/` en vez de un `navigate()` cliente-side.
- Arreglados dos redirects rotos del lado de Castor (`interfaces/castor/src/index.js` y su propio
  `LoginModal.tsx`) que apuntaban a rutas relativas `/company/`/`/admin/` inexistentes en su nginx.
- Verificado end-to-end con Chrome headless: login de admin desde Castor → redirect cross-origin →
  panel real de Pollux cargado.

## 2. Credencial real de admin
- Creada/actualizada la cuenta `admin@pbtradingsolutions.com` (password generada, guardada solo en
  la memoria de Claude — nunca en el repo) para loguear desde el formulario normal de Pollux y
  llegar al panel de admin real.
- Bug encontrado y arreglado: `interfaces/admin`'s propio store de Zustand persistía en la llave
  `'admin-auth'` en vez de `'leto-auth'` (la que usa el resto de la app) — un login real nunca
  llegaba a autenticar el admin panel después del redirect, siempre caía al fallback hardcodeado.
  Corregido; el fallback (solo para visitas directas a `/admin/` sin sesión) se dejó con el
  password de desarrollo viejo, deliberadamente sin el password real nuevo (evita exponerlo en el
  bundle de JS del navegador).

## 3. Menú de perfil (`/company/`) — limpieza completa
- El menú entero leía `useProfile()` de Stremio (siempre vacío en este fork) en vez de la sesión
  real — por eso mostraba "Anonymous user" sin importar quién estuviera logueado, y el logout no
  hacía nada. Ahora lee `localStorage['leto-user']`; logout real limpia la sesión y redirige a `/`.
- "Log in / Sign up" apuntaba a `#/intro` (onboarding de Stremio) → cambiado a `/`.
- Eliminados: Addons (ruta rota, de Castor), Play URL/Magnet link (irrelevante), Terms of
  Service / Privacy Policy / User Panel (apuntaban a stremio.com, Pollux no tiene páginas propias
  todavía). Help & Feedback ahora apunta a `mailto:commercialaffairs@pbtradingsolutions.com`.
- El logo "Pollux" a veces llevaba a una versión vieja del sitio — causa: un Service Worker viejo
  cacheado en el navegador de antes del rebuild de landing. Fix: SW no-op servido en
  `/service-worker.js` desde nginx (mismo patrón ya usado en Castor).
- Hallazgo de bono: `demo.company@pollux.com` tenía la password desincronizada de la documentada;
  restablecida a `demo1234`.

## 4. Checkout único (worktree eliminado)
- Había dos copias del proyecto desde el split: MAIN (`pb-website`, rama `main`) y un worktree
  separado (`pb-website-pollux-v2`, rama `pollux/domain-seo-login-v2`) que era el que realmente
  corría en Docker. El worktree tenía un commit completo (`5bbb3c43`) nunca mergeado a `main` —
  justo lo que causó el hallazgo del punto 3 (la validación `company_name` en `auth.py`).
- Auditado el contenido de ambos checkouts con diff completo; reconciliado sin pérdida de datos
  (contenido único de cada lado copiado al otro antes de espejar); MAIN quedó idéntico al worktree.
- Confirmado que Docker Compose corre igual desde MAIN (reconoce contenedores por nombre de
  proyecto, no por ruta — no hizo falta tocar `docker-compose.yml`).
- Worktree eliminado (`git worktree remove --force` + carpeta vacía borrada). La rama
  `pollux/domain-seo-login-v2` se dejó intacta (no se borró) para no perder el historial.
- **A partir de hoy: un solo checkout** — `pb-website/products/portal/pbsds-pollux-app`, rama
  `main`. Ya no aplica el flujo "editar en MAIN, copiar al worktree".
