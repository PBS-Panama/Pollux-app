## Root cause analysis — 502 on FastAPI

Three independent issues stacked:

| Layer | Problem | Fix |
|-------|---------|-----|
| Python import | All DB migration code (600+ lines) ran at module level, blocking the Python import chain before `app = FastAPI()` | Moved all DB code into `_db_startup()` regular function, launched in a `daemon=True` background thread from a minimal `lifespan` |
| uvicorn internals | uvicorn 0.30.6 runs `lifespan.startup()` BEFORE binding the TCP socket — moving code into `lifespan` (without thread) still blocked port binding | Background thread pattern: `lifespan` yields immediately; DB code runs concurrently |
| Cloud Run CPU throttling | Default Cloud Run CPU throttling starves Python's import chain when no request is active → uvicorn never starts even after 4+ minutes | `--no-cpu-throttling` flag on `gcloud run deploy` |

The local `docker run` test (same supervisord + same code) worked perfectly — the Cloud Run CPU throttling issue only appears in production.

## Files changed

### `backend/app/main.py`

Major restructure (609 lines → 638 lines):

1. Added top-level imports: `from contextlib import asynccontextmanager`, `import threading`, `import time`
2. Moved inline mid-file imports to top: `import json as _json`, `from app.db.exam_seeds import ...`, `from app.db.learning_seeds import ...`, `from app.services.compliance_engine import ...`
3. Wrapped ALL DB migration + seed code into `_db_startup()` regular function with 12-attempt retry loop (5s sleep between attempts):
   ```python
   def _db_startup():
       for _attempt in range(12):
           try:
               Base.metadata.create_all(bind=engine)
               # ... all migrations and seeds ...
               print("[leto-api] DB startup complete", flush=True)
               return
           except Exception as _e:
               print(f"[leto-api] DB startup attempt {_attempt+1}/12 failed: {_e}", flush=True)
               if _attempt < 11:
                   time.sleep(5)
       print("[leto-api] DB startup failed after 12 attempts", flush=True)
   ```
4. Minimal lifespan that yields immediately:
   ```python
   @asynccontextmanager
   async def lifespan(app: FastAPI):
       threading.Thread(target=_db_startup, daemon=True).start()
       yield
   ```
5. `app = FastAPI(..., lifespan=lifespan)` — port 8000 now binds before any DB operation.

### `backend/app/db/session.py`

Added `connect_timeout` to prevent indefinite hang when Cloud SQL Unix socket isn't ready:
```python
engine = create_engine(
    settings.DATABASE_URL,
    pool_pre_ping=True,
    connect_args={"connect_timeout": 30},
)
```

## Architecture decisions

- **`--no-cpu-throttling` is permanent** — without it, Python import chain starves on idle Cloud Run instances. This is not a startup-time bug; it's a CPU scheduling issue specific to multi-process containers.
- **Background thread pattern is permanent** — do not revert `main.py` to module-level DB code even if the Cloud Run CPU issue is fixed. The thread pattern is strictly safer (port always binds, DB retry loop handles transient Cloud SQL socket delays).
- **`connect_timeout=30`** prevents the worker from hanging indefinitely if Cloud SQL proxy hasn't started by the time `_db_startup()` first tries to connect.
