## Fase 0 — Consolidar persistencia del perfil ✅

**Problem:** profile data written to 4 destinations simultaneously (4 different PATCH endpoints + 2 localStorage keys) → divergence risk.

**Solution:** canonical facade `GET/PATCH /api/seafarers/me/profile` as single source of truth. localStorage kept as read-cache only.

### Files changed

| File | Change |
|------|--------|
| `backend/app/routers/seafarers.py` | Added `GET /api/seafarers/me/profile` + `PATCH /api/seafarers/me/profile` facade (declared before `/{seafarer_id}` to prevent FastAPI treating "me" as UUID). `_FULL_PROFILE_SELECT` query + `_profile_to_dict()` helper covering all columns across users + seafarers. |
| `backend/app/models/seafarer.py` | Added 11 new columns: `gender`, `department`, `city`, `nationalities JSONB`, `spoken_languages JSONB`, `vessel_types JSONB`, `residence_country`, `residence_province`, `reference_airport`, `emergency_contact_name`, `emergency_contact_relation`, `emergency_contact_phone`. |
| `backend/app/main.py` | Migrations for all 11 columns via `ADD COLUMN IF NOT EXISTS`. |
| `interfaces/castor/src/routes/MyProfile/MyProfile.js` | `loadProfileFromBackend` effect on mount fetches `GET /me/profile` and hydrates all state vars. `handleSave` now writes to backend first, then mirrors to localStorage as cache. |

### Key decision
`nationality` (singular, existing) and `nationalities[]` (new list) kept consistent: `nationality` is derived from `nationalities[0]` at save time. No destructive migration.
